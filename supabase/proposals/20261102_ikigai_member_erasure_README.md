# 管理者のメンバー削除

本番アプリ反映後に、同じフォルダの `20261102_ikigai_member_erasure.sql` 全文を、本番 Supabase（ebozxwiuujrnvmxienat）のSQL Editorでpostgresとして一度だけ実行します。SQLの設定だけでは誰も削除されません。途中で失敗した場合はトランザクション全体が取り消されます。既に設定済みの場合は再実行を停止します。

この作業環境には本番DBを変更する接続権限がありません。秘密鍵をチャットへ送る必要はありません。機能は既存のサーバー専用キーを利用します。SQL実行前もプラン変更は利用できます。削除はSQL未設定のまま開始しません。

## 使い方

管理者画面 → 在籍メンバー → 各人の右上「︙」から「プラン変更」「メンバー削除」を選びます。

削除は、注意事項の確認と「削除」の入力後に開始します。管理者本人・他の管理者アカウントは削除対象にできません。一般会員は削除画面にアクセスできず、APIやSQLの削除RPCを直接呼んでも削除できません。

削除開始時に対象者の利用を停止します。削除済みアカウントの古いJWT、処理中のAPI、写真アップロードによるデータの再作成も制限します。進行中の削除は一度に一件です。

途中で通信が切れた場合や画面を閉じた場合は、管理者画面に表示される「削除を再開」から続けます。旧保存先の反映を確認するため約70秒の待機があります。保存先・権限・削除結果を確認できない間は完了表示にしません。処理中の削除は取消し・復元できません。

## 削除対象

- Authのアカウント（Admin APIによるハード削除）、会員登録、プロフィール、申込、振り返り、行動チェック、プラン情報。
- 本人の成長ログ・全体トーク・リアクション。本人の投稿への構造化された参照や既読等。
- 本人が参加する個別トーク全体と、そこに紐づく索引・既読・リアクション・保存された名前。
- 本人が作成したグループ全体。**他の参加者がそのグループへ送った会話も削除します。** 他のグループでは本人の投稿・参加情報・リアクション・既読等を削除します。
- 成長ログの写真はStorage APIで実ファイルを削除します。DBの表示だけを消す方式ではありません。
- 問い合わせ・対応履歴・通知登録等。Supabaseの現在の運用保存先と、移行前のKVのコピーの両方を対象にします。
- 処理中の一時ジョブは、全処理と検証の完了後に削除します。削除済み会員の名簿や生のUIDを永久に保持する方式ではありません。

他のメンバーのプロフィール・投稿・別グループは維持します。元の既存アクセス制御、保存時暗号化、毎日2:00〜2:30のメンテナンス設定と自動点検は維持します。メンテナンス中に操作が止まった場合は、終了後に再開してください。

## 消去保証の範囲

対象はこのアプリで管理し、本人に紐付けられる稼働中のデータです。**外部サービスのバックアップ・監査ログ、送信済み通知、別端末の保存コピーやスクリーンショット、他の人が自由文に書いた情報まで、この操作で消せたとは保証しません。** バックアップやログの保持期間・削除可否は各サービスで管理します。バックアップから復元する際には、削除した情報を再取り込みしない確認が必要です。

このアプリで把握していない別テーブルの会員参照や、別バケットの本人所有ファイルが見つかる場合は、他アプリのデータを無断で消さず停止します。管理者に確認してから範囲を追加してください。

## 検証

実在の会員を削除するテストは行っていません。隔離PostgreSQL 16で権限、JWT失効後の制限、物理データ・参照の削除、共有データの維持、再書き込み防止、夜間点検との互換性を確認しています。API・Storage・Auth・旧KVの処理はモックで検証し、スマホ幅とPC幅の画面をChromiumで確認しています。
