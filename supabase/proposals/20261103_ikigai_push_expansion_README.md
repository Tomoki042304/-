# 携帯への通知・入会時の許可案内

- 入会手続きは５ステップ。最後の「携帯の通知を許可する」から、OSの通知許可と端末登録を実施。通知を拒否・非対応でも入会は完了できます。
- 未承認アカウントも自分の端末登録だけ可能。配信対象は承認済みメンバー・管理者です。
- 新メンバー承認、新しい成長ログ、全体トーク、参加中グループ、個別トーク、本人の投稿・トークへの反応、運営のお知らせをデータ保存時に配信キューへ登録します。
- 退会・プラン変更・グループの参加状態は、配信直前に再確認します。自分の操作の通知は自分には送りません。
- 設定用SQLを一度実行すると、Supabase pg_cron + pg_netが毎分、署名用の非公開トークン付きで配信APIを呼びます。トークンはSQL内で生成し、ブラウザに渡しません。
- 朝会の編集画面で開催日時（日本時間）と通知チェックを保存すると、開始30分前からプレミアム会員の許可済み端末に配信します。開催日時は１回分です。配信状況・OS・通信状態によって到着時刻は前後します。
- 朝会URL、会話本文、コメント本文は端末通知に含めません。タップ後にアプリの認証・権限チェックを通して確認します。
- キュー、配信済み端末情報、短期間の重複防止情報は既存の非公開runtimeテーブル内に保存し、メンバー削除時の消去対象に含まれます。
- 通信失敗は再試行し、端末別の配信済み記録で重複を抑えます。外部Pushサービスへの到達とDB記録の境界があるため、厳密な一回限りの配信保証ではありません。

## 有効化

本番公開の完了後、Supabase SQL Editorで `20261103_ikigai_push_expansion.sql` の全文を一度実行します。既存の運用用runtimeテーブル・会員プラン・朝会の設定が前提です。Supabaseの `pg_cron` と `pg_net` が使える必要があります。既存データの一括通知は行いません。

SQL実行後、実機で入会時の通知許可、別ユーザーによる投稿、携帯ロック画面への配信を確認してください。管理者は朝会カードの「編集」から未来の開催日時と30分前通知を保存します。

## 検証範囲

PostgreSQL16でイベント捕捉、配信先、権限、重複抑止、プラン変更、端末別再試行を確認。ローカルのcron/HTTP拡張は関数シグネチャのスタブを使用し、本番の定期実行や実機への到着は未確認です。
Chromiumで５ステップの入会、許可前にOSプロンプトを出さないこと、拒否後の継続、許可後の端末登録、朝会の日本時間変換を確認。OS APIと接続先は模擬です。実在メンバーへの通知送信や本番DB変更は行っていません。
