# 入会前の履歴と通知を分ける・自己紹介の同時保存

追加SQLは、携帯通知の設定用SQLを実行済みの本番プロジェクトで一度だけ実行します。通知の定期処理は追加しません。

通知の基準は approved_members.approved_at。承認行がない管理者は既存のチャット利用基準と同じくAuthアカウント作成日時を使います。

- 成長ログの投稿履歴は削除・除外しません。
- 成長ログの新着表示、ベル内の反応、ベル・ホームの運営通知は入会以降の発生日時だけを対象にします。
- 端末配信では、キューが作られた日時だけでなく、ログ・メッセージ・反応・運営通知の発生日時でも入会時刻を確認します。過去の投稿を後から取り込んでも、新着通知にはしません。
- 入会前に発生した通知がキューに残っていても、送信直前の確認で除外します。既にOSへ配送済みの通知は取り消しません。
- 既存の自己紹介用SQLが未実行の場合は、このSQLが必要な自己紹介の関数・制御も設定します。
- 自己紹介ノート用SQLも統合しています。自己紹介の一度の送信で、トーク本文とノート４項目が同じDBトランザクションで保存されます。両方の保存を確認してから noteSaved=true を返します。
- 既存の送信済み自己紹介は、履歴に本文が残っているものをノートへ取り込みます。既に本文まで消えた自己紹介を復元することはできません。
- トークの自己紹介メッセージを送信取消しても、既に保存された自己紹介ノートは維持します。アカウントのメンバー削除では両方を削除します。

検証：Chromiumの模擬アカウントで入会前のベル通知と新着バッジの除外、履歴表示、入会後通知の並び、自己紹介未保存時の入力保持を確認。PostgreSQL16の隔離データで入会境界・過去データ・同時保存・再送の重複防止・保存エラー時の全体ロールバックを確認。本番DBは直接変更していません。
