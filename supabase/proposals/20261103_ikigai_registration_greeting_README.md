# 登録時の挨拶と、成長ログだけの利用許可

最初の登録画面に必須の「挨拶メッセージ（一言、160文字まで）」を追加します。登録完了時に、名前・職業・一言の自己紹介が成長ログに公開されること、入力と登録完了をもって掲載とログ利用に同意することを画面内に明示します。

登録時に、本人の署名済みセッションから挨拶RPCを実行します。RPCは同一トランザクションで本人用の利用許可と自己紹介投稿を保存します。固定の投稿IDと許可記録で二重投稿を防ぎます。保存に失敗した場合は登録画面に入力を残します。

挨拶の登録だけで許可する範囲は成長ログの閲覧・本人の投稿・コメント・応援・公開投稿の写真です。approved_membersへの追加は行いません。トーク・Zoom・SHIN AI・会員一覧などの入会権限は従来の管理者承認を維持します。成長ログの投稿者の名前・写真は、公開投稿のある本人分だけを最小限のディレクトリAPIで返します。入会申込の個人情報や他のプロフィール項目は返しません。

管理者が入会を承認すると、登録済みの挨拶を全体トークと自己紹介ノートへ自動保存します。登録と承認が同時に進んでも、共通ロックにより取りこぼしと重複を防ぎます。自己紹介の新しい入力欄・ノート表示は名前・職業・一言の３項目とし、ホームの最終目標は維持します。

SQL設定は `20261103_ikigai_registration_greeting.sql` を本番のSQL Editorで一度実行してください。携帯通知用SQLの実行済み環境が前提です。直前の入会時刻通知・自己紹介ノート用SQLが未実行なら、必要な前提をこのSQL内で設定します。既存のメンバーを一括で自動承認したり、過去の自己紹介を成長ログへ大量投稿したりはしません。

公開の自己紹介と本人用の利用許可は、既存のdocuments/runtimeテーブルに保存し、既存のメンバー削除処理による消去対象に含めます。既存のRLSのメンテナンス・アカウント削除ガードは維持します。ログだけの利用者への通知はログ・コメント・応援に限定し、トークや運営・朝会等の入会者向け通知には広げません。

検証：隔離PostgreSQL16で未承認アカウントのログ権限、他会員機能の拒否、三項目の自動投稿、再送の重複防止、ログ反応通知、承認後のトーク・ノート保存、承認との同時実行を確認。Chromiumの模擬サービスで登録失敗時の入力維持と、承認待ちでのログ投稿、トークの拒否を確認。実際のユーザーデータ、本番DB、実機の通知は変更・送信していません。
