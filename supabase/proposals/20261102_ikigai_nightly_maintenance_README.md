# IKIGAI 毎日の点検

## 有効化の最後の手順

本番 Supabase（ebozxwiuujrnvmxienat）の SQL Editor に `20261102_ikigai_nightly_maintenance.sql` の全文を貼り付け、一度だけ実行します。既存データの書き換え・削除は行いません。トランザクション内の確認に失敗した場合は設定を適用しません。既に設定済みなら再実行せず停止します。

**アプリ側だけでは、ブラウザから直接 Supabase にアクセスする操作を停止できません。このSQLの実行が必要です。** この作業環境から本番DBの設定を実行する接続権限はありません。秘密鍵をチャットに貼らないでください。

SQL実行後、管理者アカウントの「個人情報の保護設定」→「点検結果を確認」で設定状況を確認できます。点検は GitHub Actions の **IKIGAI nightly maintenance audit**（main ブランチ）で手動実行もできます。初回は手動実行し、完了結果を確認してください。失敗・未実行は成功扱いにしません。

## 時間・動作

- 26:00 は翌日2:00と解釈。毎日 **02:00:00以上、02:30:00未満（Asia/Tokyo）** は停止します。
- 通常は02:30に再開します。停止・復帰の判定を、GitHubのジョブ実行時刻に依存させません。
- 新しいアプリは初期表示前に状態を取得。開いたままでも停止画面に切り替え、終了後は状態を再取得して元の画面に戻ります。入力中の文章を消すための再読み込みは行いません。初回に通信できない場合は、白画面ではなく確認・再試行画面にします。
- APIは503、Retry-After、no-storeを返します。DBは既存のPostgREST pre-request hookを保持して制限を追加し、RLSが既に有効なアプリテーブルとStorage objectsには制限ポリシーを追加します。既存の許可ポリシーや会員判定は変更しません。
- Authサービスのログイン、配信済みの静的ファイル、既に端末へダウンロードされた情報まで回収・無効化する仕組みではありません。停止前に処理を開始した書き込みを中断・巻き戻すことも行いません。既に開いている古いアプリには更新が必要です。
- service_roleは点検用に継続使用します。公開状態APIは状態のみを返し、点検結果は通常の管理者認証が必要です。停止中に一般の管理者画面を利用する例外は設けません。

## 自動点検

GitHubのデフォルトブランチmainに登録したワークフローがJST 02:03 / 02:13 / 02:23に実行要求を送ります。GitHubの混雑・停止・Actions無効化等で遅延や未実行になる可能性があります。本日の完了記録がなければ、管理者画面は未完了と表示します。

追加の共有シークレットは不要です。GitHub OIDCのRSA署名、issuer、audience、リポジトリ、mainブランチ、ワークフロー、イベント、有効期限をサーバーで検証します。実行権限を匿名・一般会員・別リポジトリに公開しません。SQLの短期リースで同時点検を抑止します。

自動確認する項目：

- SHIN AIの稼働モデルに短い合成質問を送り、応答を確認。会員の質問や知識を外部検査に送らない。
- 暗号鍵の暗号化・復号・別用途での復号拒否。
- 専用の一時レコードによる保存・取得・削除。点検以外の会員データは変更しない。
- 登録知識（最大10件）の読み取り・復号。未登録は注意、原文は結果に含めない。
- 既存の個人情報の暗号化・復号を標本確認（プロフィール等最大20件、問い合わせ等は種別ごと最大10件）。全件やバックアップの検査ではない。
- 既知の非公開テーブルのRLS・権限、写真バケットの公開設定、停止用設定・ポリシー。
- 公開対象ソースに特定形式の秘密鍵が混入していないか。未知のシークレット形式までは判定できない。
- 代表する設定ファイルURL（/.env、/.git/config、/wrangler.toml）の露出兆候。3URLのみの検査であり完全な漏洩検査ではない。
- npm CDNで直接参照するSDKの固定バージョンをOSVで既知脆弱性照会。間接依存や対象外CDNは含まない。接続できなければ未確認。
- 代表APIへの匿名アクセス。停止中は点検拒否を確認できても会員権限の判定までは確認できない。

結果は専用の非公開保存先に記録し、内容・秘密鍵・氏名・会員の質問はログに残しません。結果レコードの参照期限は90日です（物理削除の保証ではありません）。重大異常、動作異常、注意、未確認を区別します。点検レポートが生成されても、最終完了処理に失敗した場合は未完了と判定します。

## この構成で未確認の項目

**Cloudflare WAF・DDoS/通信ログ、Supabase認証/監査ログには接続できていません。** 攻撃・乗っ取り・過去の漏洩・バックアップ漏洩について「問題なし」とは表示しません。完全な侵入・漏洩検知やAI回答品質の保証ではありません。管理者画面の未確認表示を解消するには、それぞれのサービスで利用できるログと保存期間・権限に応じた別途連携が必要です。攻撃は02:00以外にも起きるため、夜間点検は常時のWAFや監視の代わりにはなりません。

## 重大異常時も停止を継続する場合（任意）

固定30分で再開する設定を初期値にしています。点検で確認した重大な権限・公開設定異常などがあった際、管理者が確認するまで停止したい場合のみ、SQL Editorで次を実行します。

```sql
UPDATE public.ikigai_maintenance_config_v1 SET hold_on_critical=true WHERE id;
```

AI応答エラーやログ未接続だけでは重大異常として停止を延長しません。原因確認後の解除はSQL Editorで実行します（通常の毎日2:00〜2:30の停止は残ります）。

```sql
SELECT public.ikigai_maintenance_release_v1();
```

緊急時に毎日の停止も含めて無効化する場合：

```sql
UPDATE public.ikigai_maintenance_config_v1
SET enabled=false,critical_hold=false WHERE id;
```

既存のpre-request hookは残しています。将来RLS対象テーブルやRPC、Storage経路を追加したときは制限ポリシーの追加と点検対象の更新が必要です。
