# 志言の実API・RLS試験結果

対象：テストSupabase `imgearpizizqkutzrpuz` のみ。
結果：46項目成功、失敗0件。合成ユーザー4件と専用データは削除確認済み。

## 試験経路

ユーザー承認後に、このクラウド環境から証明書検証付きHTTPS・既存プロキシ経由で実Auth/Data APIを使用した。合成ユーザーとして有効会員A、adminロールの有効会員B、停止会員、非会員を作成し、それぞれのパスワード認証で取得した本人JWTで試験した。メール宛先は `example.invalid`、パスワードはランダム生成。招待や再設定メールは送っていない。

管理キーは合成データの準備、合成会員Aの停止、限定した状態確認、後片付けだけに使用した。一般会員のRLS検証は本人JWT、未ログインの検証はPublishable keyのみで実施した。実在の会員データ・旧アプリのテーブル・Auth設定・本番候補は変更していない。

## 成功した操作・拒否

- A・Bによる本人の志言登録・参照・日本語／改行を含む更新。
- A・Bによる他人の志言の参照・登録・更新の拒否。adminロールのBにも同じ制限が適用される。
- 所有者・作成日時の変更、志言の削除を拒否。通常の内容更新でcreated_atが保持される。
- 本人の会員状態参照、会員ロール変更・会員行削除の拒否。
- 未ログイン・非会員・停止会員の志言参照・登録・更新を拒否。停止会員本人の既存志言も取得不可。
- 非会員の自己会員登録・自己管理者化を拒否。
- 絵文字500文字の内容を受け付け、501文字・空文字・空白だけを拒否。
- 古いupdated_atを条件にしたUPDATEは更新0件となり、新しい内容を上書きしない。
- 再ログイン後も更新後の複数行の志言を取得できる。
- Aを停止した後、既存JWTでの新しいGET・PATCHが拒否される。本人の停止状態は参照でき、自己再有効化は拒否される。
- 拒否操作後も、合成志言が正常更新後の既知の値から変わっていない。

参照・更新の拒否はHTTPエラーだけで判定せず、RLSによる空配列・更新0件も確認した。上記を独立した46項目として実行した。
