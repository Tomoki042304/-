# 公開先の志言機能・実API試験

対象：`https://shidoroku-dev.pages.dev` とテストSupabase `imgearpizizqkutzrpuz`。
対象機能：コミット `af210f9` の公開後の志言登録・編集。
結果：19項目成功。試験用Authユーザー1件と専用データは削除確認済み。

## 試験方法

ユーザー承認後にAuth管理APIでランダムな合成ユーザーを1件作成し、専用会員行を有効状態で用意した。メール宛先は `example.invalid`、メール送信は行っていない。

公開中のHTML・JavaScriptをChromiumで実行し、実際のフォームから本人JWTでAuth/Data APIにアクセスした。模擬APIは使っていない。通信は標準の証明書・ホスト名検証付きHTTPS経路で中継した。前回と同じ方式であり、制約は `live-login-test-results.md` を参照。TLS検証は無効化していない。

管理キーは合成ユーザー・会員行の準備と後片付けだけに使用した。志言の登録・更新は画面から本人権限で実施した。プロフィールには未保存の試験文字列を入力しただけで、プロフィールの書き込みリクエストが送られていないことも確認した。

## 成功した19項目

1. 公開ログイン画面を表示。
2. 実Authログインと専用会員資格確認に成功。
3. 新規会員の志言は未登録として表示。
4. 改行付き日本語の志言を初回INSERTで保存。
5. 保存済みの志言を実APIから読み直せる。
6. 別の改行付き日本語の志言へUPDATE成功。
7. 志言の書き込みは本人ID＋contentのINSERTとcontentのみのUPDATE各1回。UPDATEには本人ID・updated_at条件を含む。
8. 会員資格の再確認後も、志言とプロフィール双方の未保存入力を保持。
9. 再確認後も各入力フォームは1つだけで重複しない。
10. セッションはlocalStorageに保存されない。
11. 390px幅で横スクロールがない。
12. 再読み込みでログイン画面へ戻る。
13. 1280px幅で再ログイン成功。
14. 再ログイン後に更新後の志言が読み込まれる。未保存の試験入力で上書きされていない。
15. PC幅でも保存済み志言を改行付きで表示。
16. ログアウト後にログイン画面へ戻る。
17. ログアウト後の `#/member` 直接アクセスはログイン画面へ戻る。
18. ブラウザのページエラーがない。
19. HTTPS中継でリクエスト失敗がない。
