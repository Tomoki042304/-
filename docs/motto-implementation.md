# 志言の登録・編集

状態：ローカル実装と模擬API試験済み。専用SQLは別チャットで適用成功し、構造・権限・RLS3件・トリガーが指定どおりとのユーザー報告を受領した。続いてこのクラウド環境から実API・RLS試験46項目が成功し、承認済みの合成ユーザー4件と専用データは削除確認済み。ユーザー承認を受け、GitHub mainへの保存とCloudflare自動デプロイの対象とする。公開先での志言の画面保存試験は未実施。

## 今回の仕様

- 会員本人が大切にしている言葉を1件保存する。500文字以内で改行可能。
- 本人だけが閲覧できる。メンバー公開、複数件管理、履歴、削除は今回含めない。
- 会員ホームにプロフィールとは別の「志言」欄を追加する。読み込み・保存の失敗はプロフィール機能を妨げない。
- 空白だけ・500文字超を拒否。文字数はUnicodeコードポイント単位で数える。前後の空白を取り除き、内部の改行は維持する。
- 保存済みの志言は改行を保って表示し、HTML文字列も通常のテキストとして表示する。
- 初回INSERT、以降はcontent列だけをUPDATEする。UPDATEには本人IDと取得済みupdated_atを指定し、他の画面からの新しい更新を確認なしで上書きしない。
- 失敗・タイムアウト・更新0件では成功表示を出さず、入力を保持する。書き込みを自動再試行せず、「志言の最新情報を確認」で読み直してから保存する。
- 会員資格の再確認中は表示・保存を止め、入力状態は維持する。再読み込みやログアウト後の未保存入力は保持しない。

## SQL案

`supabase/proposals/20261027_shidoroku_mottos.sql`。自動適用されるmigrationsディレクトリには置いていない。

対象はテスト環境 `imgearpizizqkutzrpuz` のみ。追加するものは以下。

- `public.shidoroku_mottos`：user_id主キー（専用会員行を参照）、content、created_at、updated_at。
- RLS：有効会員本人だけのSELECT / INSERT / UPDATEポリシー3件。
- 権限：既定の広い権限を新規テーブルで取り消し、authenticatedにSELECT・指定列のINSERT / UPDATEのみ付与。anon / PUBLICには付与しない。service_roleにCRUDを付与。
- 日時管理トリガー1件：既存の専用関数 `public.shidoroku_stamp_record()` を参照する。関数を上書き・変更しない。

テーブル作成からRLS・権限設定までを1トランザクションで実行する。同名オブジェクトがあれば上書きせず失敗させる。既存テーブル・Auth設定・デフォルト権限・旧アプリ用の関数は変更しない。

### 適用前確認

1. 接続先Project IDが正しいことをSQL実行ツールや管理画面で確認する。SQL自身では確実なProject ID照合を行えない。
2. 同名テーブル・ビュー・型・関数の衝突がないことをメタデータで確認する。
3. 専用会員テーブルと既存の専用日時関数が存在し、関数が承認済みのSECURITY INVOKER・空search_path・所有者とcreated_atの変更拒否／保持を行う定義であること、適用者にトリガー作成権限があることを確認する。
4. DDLイベントトリガーが今回の権限設計に干渉しないことを再確認する。既定権限による付与はSQL内で取り消す。
5. ユーザーのSQL適用承認を得てから、全文をまとめて実行する。失敗した接続はROLLBACKし、自動修正・再適用しない。

適用後はテーブル構造・権限・RLS3件・トリガーをメタデータで検証する。その後の実データ試験には合成ユーザーと専用データの作成・削除承認を別途得る。既存会員や旧テーブルのデータを試験に使用しない。
