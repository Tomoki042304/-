# プロフィール表示・編集の実装記録

状態：ローカル実装・模擬APIによる検証済み。ユーザー承認を受け、GitHub mainへの保存とCloudflare自動デプロイの対象とする。公開先での実API保存は未検証。実データの追加・変更、DB設定変更は行っていない。

## 利用者の操作

ログイン後、有効会員の会員ホームに「プロフィール」を表示する。プロフィールがあれば保存済みの表示名を読み込み、なければ初回登録を案内する。編集できるのは表示名だけ。前後の空白を取り除き、空欄・80文字超を拒否する。文字数はPostgreSQLのchar_lengthと同じUnicodeコードポイント単位で扱う。

初回保存は本人IDと表示名のINSERT。既存行の保存は表示名のみのUPDATEで、user_idや日時などは送信しない。UPSERTは使わない。更新条件には本人IDと最後に読んだupdated_atを指定し、別画面で更新された行を確認なしに上書きしない。

保存後は返された本人の行と表示名を検証してから成功表示を出す。更新0件・APIエラー・タイムアウト・不正な応答では成功と扱わない。通信失敗時は保存されている可能性もあるため、書き込みを自動で繰り返さず、入力を保持したまま「最新情報を確認」で再取得してから明示的に再保存する。再取得中も入力状態は保持する。

会員資格の定期確認・フォーカス復帰で表示が一時的に閉じても、同じログインユーザーの編集内容は維持する。資格が未確認・無効な間はプロフィールを描画せず、保存も開始しない。ログアウト・ページ再読み込み後の未保存入力は保持しない。

認証とデータ操作には既存の専用RLSを利用し、ブラウザの画面制御だけには依存しない。会員停止などによるRLS拒否も保存失敗として扱う。成功後に別画面から更新された場合など、画面表示が常に最新であることは保証せず、再取得と保存時の競合検出で対応する。
