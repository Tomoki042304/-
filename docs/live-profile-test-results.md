# 公開先プロフィール機能の実API試験

対象：`https://shidoroku-dev.pages.dev` とテストSupabase `imgearpizizqkutzrpuz`。
対象機能：コミット `c94d459` の公開後のプロフィール登録・編集。
結果：17項目成功。試験用Authユーザー1件・専用会員行・プロフィールは削除確認済み。

## 試験方法

承認を受け、Auth管理APIで `example.invalid` 宛ての合成ユーザーを1件作成し、専用会員行を有効状態で用意した。パスワードはランダム生成し、メール送信は行っていない。公開中のHTML・JavaScriptをChromiumで実行し、フォームを操作して本人のJWTで実Auth/Data APIにアクセスした。

ブラウザの通信は既存プロキシと標準の証明書・ホスト名検証を使うHTTPS経路で中継した。前回と同じ方式であり、詳細・制約は `live-login-test-results.md` を参照。模擬API応答やTLS検証無効化は使っていない。秘密キーは合成ユーザー・専用会員行の準備と後片付けにのみ用い、プロフィールの登録・更新は画面から本人権限で行った。

## 成功した17項目

1. 公開ログイン画面の表示。
2. 実Authログインと専用会員資格の確認。
3. 新規会員のプロフィールが未登録として表示される。
4. 初回表示名登録のINSERT成功。
5. 「最新情報を確認」で実APIから保存済み表示名を読み直せる。
6. 日本語の別の表示名へのUPDATE成功。
7. 画面からの書き込みが、本人ID＋表示名のINSERTと、表示名だけのUPDATE各1回である。UPDATEは本人ID・直前のupdated_atを条件に含む。
8. セッションがlocalStorageに保存されない。
9. 390px幅の会員ホームに横スクロールがない。
10. 再読み込みで再ログインが必要になる。
11. 1280px幅で再ログインが成功する。
12. 再ログイン後も更新後の表示名が読み込まれる。

14. ログアウトでログイン画面へ戻る。
15. ログアウト後の `#/member` への直接アクセスではログイン画面が表示される。
