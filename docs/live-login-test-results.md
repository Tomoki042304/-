# 公開先ログイン画面の実API試験

対象：`https://shidoroku-dev.pages.dev` とテストSupabase `imgearpizizqkutzrpuz`。
結果：9項目成功。今回作成した合成Authユーザー1件と専用データは削除確認済み。

## 試験経路

公開先のHTML・JavaScriptを読み込み、Chromiumで実際のログインフォームを操作した。模擬のAuth/Data API応答は使用していない。

このクラウド環境のChromiumはプロキシ証明書を直接信頼できなかったため、ブラウザのネットワークリクエストを、既存プロキシと標準の証明書・ホスト名検証を使うPython HTTPS経路へ転送し、実際の応答をブラウザに渡した。TLS検証の無効化、Cloudflare設定変更、API応答の捏造は行っていない。ブラウザからプロキシへ直接通信する経路や、ユーザー端末固有の通信経路を検証したという意味ではない。

## 確認した9項目

1. 公開先で会員ログイン画面が表示される。
2. 合成ユーザーの実Authログインが成功し、有効な専用会員行を確認して本人の会員IDを表示する。
3. localStorageへセッションが保存されない。
4. 390px幅の会員ホームに横スクロールがない。
5. 再読み込み後はログイン画面へ戻る。
6. 1280px幅でも再ログインして会員ホームを表示できる。
7. ログアウト後はログイン画面へ戻る。
8. ログアウト後に `#/member` を直接開いても会員ホームには入れない。
9. 試験中のブラウザページエラーがない。

## 合成データと後片付け

ユーザー承認の範囲内で、ランダムな識別子とパスワードを使い、`example.invalid` 宛ての合成ユーザーをAuth管理APIで作成した。メール送信は行っていない。有効な一般会員の専用会員行を1件追加し、そのアカウントで試験した。

試験終了後、記録した今回のユーザーIDだけをAuth管理APIで削除し、再取得が404であることを確認した。専用会員・プロフィールテーブルも今回のIDだけで限定検索し、残存行がないことを確認した。既存ユーザー・既存テーブル・Auth設定・本番候補は変更していない。

キー・パスワード・JWTをログやリポジトリに保存していない。IDと結果のみのローカル実行記録は `/workspace/.shidoroku-tools/live-login-556abfaa-fe54-4e3a-913e-c8336c0c328b.json`。

## 未確認の範囲

iPhone実機、メール招待・パスワード再設定、長期間の利用、実会員の登録・運用は未検証。停止・他人へのアクセスなどのRLS実API試験37項目は `membership-test-results.md` の別試験を参照。Auth共有による既存アプリへの権限範囲は引き続き設計上の制約として残る。
